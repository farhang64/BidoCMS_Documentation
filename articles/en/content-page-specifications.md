# Page specifications

Open **Pages**, select a page language, and open **Specification**. Specifications are named data fields that the selected page type or theme can use to display attributes on the website.

## Fill in existing specification values

1. Locate the field under its **family** group.
2. Enter a value or select an option. A field with multiple slots accepts more than one value up to its configured maximum.
3. If the field has a **description** area, add the optional descriptive text.
4. Select the row's **Save**. Repeat for other fields.

The panel can show corresponding values from other languages for reference. Saving applies to the current language detail. The theme controls which attributes appear publicly and how they are labeled.

## Create a specification definition

Select **Add New Specification**. The first **site node type** selector actually chooses the value's data type. The second chooses the site page type.

| Field | Purpose |
| --- | --- |
| name | Name or key of the specification. |
| family | Group heading used to organize fields. |
| description | Guidance shown alongside the value input. |
| maximum select data | Number of value slots in the editor. |
| title | Optional label shown alongside the name. |
| need extra text | Adds a separate description input for the value. |
| First site node type field | Data type. Choose **String**, **Number**, **Float**, **Boolean**, or **List**. |
| list data | For **List**, enter each allowed option on its own line. |
| Second site node type field | The intended site page type for the specification. |

Save the definition. Reopen the tab to load any new available value row. A definition's **Save** configures the field. The value row's **Save** stores the content for the page. Use the definition card's trash icon and confirmation to delete a custom definition after reviewing where it is used.

If the field is missing, check the selected language, the page's **Node type**, and the specification's target type.
