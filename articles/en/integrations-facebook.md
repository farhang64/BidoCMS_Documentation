# Connect a Facebook Page and manage posts or messages

Open **Social → Facebook** to manage Facebook Pages available to the website. Posts, Inbox and Profile are scoped to the selected Page.

## Connect and verify your Page

1. Choose **Connect Facebook** and sign in to an account that manages the intended Page.
2. Approve the relevant Facebook permissions and choose the Pages you want to connect. One CMS installation can connect multiple Facebook Pages.
3. Select the Page tab and open **Profile**. Check the displayed identity and status, and optionally choose **Open on Facebook**.
4. Use **Refresh profile** to update the displayed information. Use **Add Facebook Page** to connect another Page, **Reconnect Facebook** to renew authorization, or **Disconnect** to remove the selected CMS connection.

## Publish and manage posts


1. In **Posts**, choose **Create post** if publishing access is available.
2. Enter **Post text**. Optionally choose one **Link**, one **Public image URL** or one **Photo** upload. The URL must use HTTPS and Facebook must be able to fetch the image.
3. For a photo upload, select one JPEG or PNG, up to 5 MB.
4. Confirm the target Page and choose **Publish post**.
5. Use **Refresh posts**, then open the resulting post to review details. If the provider and Page grant allow it, **Edit post** updates the text and **Delete post** removes the post from Facebook.

In post details, **Comments** can show existing comments. Use the available reply, hide, show or delete controls according to the Page's permissions. A visible post does not imply moderation access.

## Read and respond to Page messages


Open **Inbox**, select a conversation and review its messages. Use **Load older messages** to browse backward and the relevant refresh control for the conversation list or thread. If Facebook permits a response and the Page has message write permission, type the reply and choose **Send reply**.

An app pending setup or an account missing provider access can limit a section. Check the Meta app configuration, CMS submenu grant and Page role. If a single thread is unavailable for replies, read the reason displayed in that thread.
